# Session Cartographer 0.7.1

A follow-up to 0.7.0. The attribution migration under-repaired: events recorded from
a **subdirectory** of a worktree were skipped.

## Who needs this

Anyone who ran the 0.7.0 migration. Re-run it — the pass is idempotent and picks up
only what was missed:

```bash
node scripts/migrate-project-attribution.js            # dry run
node scripts/migrate-project-attribution.js --apply
```

If the dry run reports `0 event(s) would be repointed`, you were unaffected and there
is nothing to do.

## What was wrong

The migration repointed a record only when its `project` equalled `basename(cwd)`. The
hook it repairs, though, derived the project from `git rev-parse --show-toplevel`, which
returns the worktree **root** no matter how deep the working directory was. An event
recorded in `…/worktrees/confident-yalow-e1cdc6/apps/capacitor/android` therefore carried
`confident-yalow-e1cdc6` as its project alongside a much deeper `cwd`, and the check
skipped it.

The signature now also accepts a `project` matching the basename of the cwd's own
toplevel. On the development corpus that recovered 18 further events across 2 phantom
projects.

Nothing else changed, and the 0.7.0 write-time fix was never affected — new events were
always attributed correctly regardless of directory depth.
